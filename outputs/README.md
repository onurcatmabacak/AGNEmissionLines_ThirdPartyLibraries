# `outputs/` — products (deliberately not shipped)

These were about **2 GB**: fit tables, chains, figures, cubes and reports from 33
tools, and they are no longer committed (nor present in the git history).

The results are not lost:

* [`docs/RESULTS.md`](../docs/RESULTS.md) — one row per committed product with
  its headline numbers, generated by `pipeline/build_results_summary.py`;
* [`docs/SCIENCE_RESULTS.md`](../docs/SCIENCE_RESULTS.md) — the statistical
  results and where independent tools disagree;
* [`docs/CAVEAT_MATRIX.md`](../docs/CAVEAT_MATRIX.md) — what each tool may and
  may not claim.

What remains here is one `README.md` per product: the analysis narrative and the
caveats that belong next to the numbers.

To regenerate a product, restore its input (`inputs/README.md`) and run the tool:

```bash
bash pipeline/runners/run_<tool>_docker.sh <input> outputs/<tool>/<SOURCE_KEY> \
     --config configs/<tool>/<variant> --source-key <SOURCE_KEY>
```

The layout `outputs/<tool>/<SOURCE_KEY>[/(<variant>)]/` is unchanged, and
`pipeline/build_output_manifest.py` rebuilds the catalogue once products exist.
